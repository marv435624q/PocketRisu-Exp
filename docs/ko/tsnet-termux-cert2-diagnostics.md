# Termux tsnet cert2 diagnostics — 2026-11-05

Base commit: `1aac88da628f8da7f54d69fb071fa3904f88abb6` (`tsnet-v1.104.5-cert1`).

The real cert1 Termux run reached `Running` with `registered:true`, but HTTPS preparation ended with `deadline` and `verification:null`. That proves the self-HTTPS GET was never reached, but cert1 did not expose which certificate/ACME/listener step consumed the time.

## cert2 diagnostic contract

cert2 keeps the existing registration and state guard. It does not clear state, delete a device, force login, or change normal non-diagnostic startup.

The opt-in `--verify-https` path now emits only structured allowlisted diagnostics:

- top-level preparation: `prerequisites`, `certificate`, `post-certificate`, `listener`
- ACME progress: `account`, `order`, `dns`, `issuance-wait`, `certificate`
- state: `start`, `done`, `error`
- network class where an error exposes it: `dns`, `tcp`, `tls`, `timeout`, `other`
- elapsed milliseconds, capped at 300000

Tailscale's ACME source is derived deterministically from the pinned cert1 source archive. Diagnostic-only markers are inserted around the existing ACME calls, but they are enabled only for the explicit cert2 verifier request, identified internally by `CertPairWithValidity(..., 1ns)`. The sidecar additionally accepts marker logs only while that request is active and only from the target certificate-domain log prefix. Background renewal for another domain therefore cannot contaminate the timing stream. The parser never formats or forwards logger arguments or prefixes, so certificate domains, order URLs, DNS TXT values, keys and account data are not copied into verifier results.

## Retry and exit handling

A preparation failure in diagnostic mode gets one bounded retry. This fixes the cert1 behavior where the first transient failure ended the probe immediately, while avoiding an unbounded series of ACME attempts. Registration-required, zero-Noise-key, NeedsLogin and NeedsMachineAuth remain terminal in the external verifier.

The cert2 verifier also drains a final JSON object even when the child exits without a trailing newline. Historical `https-error` rows do not poison a later successful TLS/HTTP verification; the final verdict is based on the child exit code and final trusted HTTPS verification.

## Build boundary

`CANDIDATE.json`, build identity and output directory use `tsnet-v1.104.5-cert2`. The exact final source ID, long version, ARM64 binary hash and packaged provenance must be generated by a fresh pinned Go 1.27.3 build. This source commit does not invent those values.

No GitHub Actions, main merge, state reset, real account test or device HTTPS test is performed by this source commit.
